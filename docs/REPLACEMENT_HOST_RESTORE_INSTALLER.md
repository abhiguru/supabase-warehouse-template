# Replacement-host v4 restore installer and isolated 2026-09-28 drill

This procedure restores an existing warehouse instance. It never runs `setup.sh`, starts `cloudflared`, changes DNS, sends an OTP, or authorizes cutover. The original pilot VM remains live. A successful run is an **isolated replacement-host rehearsal**, not production recovery or clean-host acceptance. Use a new empty private state directory for every attempt; failed states are evidence and cannot be resumed by the installer.

The implementation is `scripts/restore-replacement.py`. It accepts only a privately extracted v4 backup from `scripts/prepare-recovery-bundle.py`. The intake script verifies the outer USB tar hash, every archive path/type/duplicate, nested file checksums, and storage archive safety before extraction. The restore script checks the pinned source ancestry, backup image, private ownership/modes, manifest identity, all absolute paths in `compose.env` and the saved tunnel config, host port and Docker project/volume/network collisions, exact core service set, bind sources, an internal network, and absence of public ports. It deliberately remaps the three state filesystem paths and uses a distinct **host-local Compose project**; the original instance ID, canonical origin, credentials, and manifest bytes stay unchanged. The copied tunnel credential remains in private extraction; its config is saved only as `cloudflared.INACTIVE.yml`.

The `restore` action builds only the pinned database image, creates and inspects an internal Docker network, and proves an external TCP connection fails from a credential-free container **before** starting the database with recovered credentials. It replays `globals.sql` into the new cluster, including role attributes, password hashes, settings, and memberships, then requires a normalized exact `pg_dumpall --globals-only` match. It restores the logical dump with original object owners into `warehouse_restored_stage`, replays ACLs after objects exist, temporarily grants the archived `postgres` event-trigger owner superuser only during staging, and proves its full `pg_authid` state is unchanged afterward. Integrity output, every archived COPY row, all sequence values, and storage bytes must match before the freshly initialized bootstrap database is replaced. The installer refuses an initialized data directory or a repeated run.

The `build` and `cache` actions prepare the other seven core images and Functions dependencies. Cache preparation uses source files and a dummy manifest with no live credentials, then proves Functions starts with `network none`. `verify` starts the ten core services only on the internal network, checks identity, original anon/service credentials, private bucket and object bytes, anonymous denial, catalog owners and privileges, live-container outbound TCP failure, and 30 seconds of healthy recovery after an owned database restart. Raw Compose, PostgreSQL, Docker, HTTP and cache output stays under the private state's `evidence/` directory. `stop` stops only containers bearing this checkout's Compose ownership labels and retains private data and diagnostics.

## Operator sequence for another isolated drill

First run `sudo -n true` and inventory disks, mounts, free space, listening ports, containers, and running services. Stop if effective noninteractive sudo is unavailable; configure it with `visudo` outside chat. Use the filesystem UUID, not a guessed `/dev/sdX` name. Confirm the USB is not mounted elsewhere, then mount it read-only as the installation user, using `uid=$(id -u),gid=$(id -g),fmask=0177,dmask=0077,ro,nosuid,nodev,noexec`. Do not alter `Archive.zip` or any older backup. Keep the USB tar and every extracted file outside Git in private directories. Do not print their contents or raw logs.

For the tested backup and reviewed source pair, this is the repeatable command
sequence. The new `build` action was added after the first passing runtime
check and then exercised against the stopped state; future drills should use
the order shown here.

Run from the reviewed checkout. Use a **new** state path each time; `replacement-attempt-02` above is retained evidence and cannot be reused. The exact `mount` command is for this installation user's UID/GID and this VM's new mount point; inspect existing mounts first. This drill's fresh checkout was created under `umask 077`, so tracked source bind files were restored to Git's 0644/0755 modes behind the private 0700 checkout parent before container startup. The installer now fails if a source bind is unreadable by container users. Do not relax backup or credential permissions. Docker group access used `sg docker`; the Docker socket was not made world-writable. Place the USB tar, extracted bundle, state, and private logs outside the checkout. The private output directory for the disposable verifier must already exist with mode 0700, and the shell should have `umask 077` so its log is 0600. On a clean host with Node 22.18+ in `PATH`, the `PATH=` prefix is unnecessary.

## Still open

This VM already had Docker, Node, cached images and prior drill state. A final clean-host run using only off-host media is untested. The backup contains one real private document but no goods-receipt rows or other representative business transaction set. A second independent backup, physical-host and unattended guest restarts, approved RPO/RTO and retention, independent custody, optional monitoring/pooler/CUPS volumes, real handset/OTP behavior, external HTTPS/mobile routing, and a separately authorized single-connector cutover remain untested. The operator's explicit **unencrypted-backup risk exception** remains; confidentiality is not established. Keep the original pilot as the only live connector until a separate cutover plan and approval cover writer freeze, final backup or delta, route ownership, rollback and reconciliation.
